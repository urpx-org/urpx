# Contributing to URPX

Thank you for your interest in contributing to URPX. URPX is developed
under the Linux Foundation Energy Standards and Specifications (LFESS)
Working Group process.

## Licensing of contributions

By contributing to this repository you agree that your contribution is
licensed under the same terms that apply to the corresponding file
category at the time of your contribution:

- **Currently (pre-Draft stage):** all contributions are licensed
  under Apache License, Version 2.0. See [LICENSE](LICENSE).
- **After Working Group Draft acceptance:** contributions to
  specification files will be licensed under the W3C Document License,
  and contributions to dataset files under CDLA-Permissive-2.0.
  Contributions to source code and meta files remain Apache-2.0.

See [TRANSITION.md](TRANSITION.md) for the full license transition plan.

## Developer Certificate of Origin (DCO)

All contributions must include a `Signed-off-by` line in every commit.
Adding this line certifies that you wrote the contribution — or
otherwise have the right to submit it under the applicable license —
per the [Developer Certificate of Origin, version 1.1](https://developercertificate.org/).

Append a DCO line by running:

```
git commit --signoff
```

The line looks like this:

```
Signed-off-by: Your Name <you@example.com>
```

Pull requests missing `Signed-off-by` on every commit will be asked to
rebase and re-sign.

## How to contribute

1. **Issues.** Open a GitHub issue to propose changes, report bugs,
   or discuss ideas before submitting larger contributions.
2. **Pull requests.** Fork the repository, make your changes on a
   feature branch, include DCO sign-off on every commit, and open a
   pull request against the default branch.
3. **Reviews.** Contributions are reviewed by the URPX Working Group.
   Substantial changes to specification text require Working Group
   consensus.

## Code of conduct

URPX follows the Linux Foundation's code of conduct. Be kind, be
constructive, assume good faith.

## Security issues

Do **not** open public issues for security concerns. See
[SECURITY.md](SECURITY.md) for responsible disclosure.
